# Manuscript Meta-Leak Pitfalls

Use this note when drafting or reviewing novel prose under the military-thriller-team workflow.

## Problem

During a chapter draft, an internal reviewer/persona name slipped into manuscript prose as a joke/meta aside. That breaks immersion and exposes the production workflow inside the fictional world.

## Rule

Keep a hard boundary between:

- **Manuscript prose:** only in-world characters, in-world institutions, and in-world knowledge.
- **Review files / process notes:** persona names, workflow labels, review roles, gate language, and craft commentary.

## Self-check

Before accepting a chapter draft, search the manuscript for internal/process terms that should only appear in reviews or project tracking, including:

- reviewer/persona names: Alex, Jordan, Casey, Hayes, Vale, Morgan, Riley, Quinn, Cross, Sam, Mason
- workflow terms: reviewer, review gate, gate status, PASS WITH RESERVATIONS, skill, persona, agent, prompt
- model/tool/meta terms: LLM, AI, assistant, Hermes, skill library

Do not blindly delete real in-world names if one later becomes a legitimate character name; inspect context. The goal is to catch production-language leakage, not ban ordinary names forever.

## Fix pattern

- Remove the meta/persona reference entirely if it is a joke or aside.
- Replace craft-commentary wording with in-world perception.
- Keep persona reasoning in the review file, not in chapter prose.
