# Follow-On Book Launch Workflow

Use this when the author finishes or signs off one novel and asks to propose or start the first follow-on book in the same series.

## Trigger

Author signals include:
- "assume we're happy with this novel, propose the follow-on"
- "create a new directory and start the process"
- approving a sequel pitch with "sounds good" / "continue"

## Context to Reuse

Before proposing the follow-on, read the current book's:
- `rolling-summary.md`, especially **Active Plot Threads for Book 2**
- final concerns log / retrospective notes, if present
- `AGENTS.md` current-state and non-negotiable continuity anchors
- final review notes if they define unresolved statuses or series hooks

Do not re-open the completed manuscript unless needed. Use the prior project's summary/open-thread files as the efficient sequel seed.

## Proposal Shape

For an informal follow-on proposal, give:
- working title options and a recommended title
- series position
- core hook / one-line pitch
- how it differs from the previous book's engine
- protagonist, spouse/co-lead, handler, local/host-nation voice, antagonist functions
- act-level shape
- open-thread payoffs and what remains unresolved
- risks/reservations with mitigations

Keep the proposal commercial and terminal-friendly; do not create formal files until the author asks to start the project.

## When the Author Says to Start

1. Create a new sibling directory under the series root with a slug from the working title.
2. Initialize standard directories: `concepts/`, `characters/`, `settings/`, `research/`, `mission/`, `chapter-briefs/`, `chapters/`, `reviews/`, `exports/`.
3. Write `concepts/seed.md` from the approved sequel pitch and prior book open threads.
4. Write `AGENTS.md`, `progress.md`, `rolling-summary.md`, and `IDEAS.md`.
5. If the author has already approved the pitch, proceed through Stage 1 in the same turn: premise options, formal Alex/Morgan/Vale review, fixed final premise, tracking updates, and stop at the Stage 2 author gate.

## Stage 1 for Sequels

Premise options should vary the sequel engine, not cosmetic surface:
- aftermath/accountability engine
- unresolved-hostage/witness recovery engine
- hidden-institution/recruitment trap engine
- family/public-inquiry/information-siege engine

Then recommend a hybrid if different options solve different sequel needs.

## Stage 2 for Sequels

Character profiles must explicitly handle:
- returning protagonist's changed state after Book 1
- spouse/co-lead agency escalation, not repetition
- unresolved named-thread payoff strategy
- new institution faces introduced by function, not exposition
- domestic baseline if the previous book ended in crisis: family, routines, bills, children, relatives, ordinary life trying to resume
- recommended fate/resolution balance for unresolved threads, with author decision flags

## Common Pitfalls

1. **Repeating the previous book's crisis engine.** The sequel should inherit consequences, not replay the same operational shape.
2. **Letting the series institution become omnipotent.** Reveal hidden units through authority, constraints, records, and discomfort.
3. **Paying off everything too neatly.** Resolve enough to satisfy readers; preserve cost and future pressure.
4. **Forgetting domestic gravity.** If characters return home after trauma, show what the next call costs in ordinary life.
5. **Turning unresolved civilians into plot tokens.** Each unresolved name needs a fate strategy and ethical use.
