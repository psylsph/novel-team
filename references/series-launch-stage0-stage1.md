# Series Launch: Stage 0 → Stage 1 Pattern

Use this when starting the first book in a military/cyber thriller series from a raw author premise.

## Session Resumption: Pre-existing Seed

If a session starts and the project directory already has a `seed.md` (at root or in `concepts/`) but no `AGENTS.md`, `progress.md`, or `rolling-summary.md`:

1. Read the seed. Check whether Stage 0 is complete (all checklist items ticked, all clarifications captured).
2. If Stage 0 is complete: initialize project structure immediately (directories, AGENTS.md, progress.md, rolling-summary.md), copy seed to `concepts/seed.md` if it is at root level, and proceed directly to Stage 1. Do not re-ask for the seed. Do not re-load extensive references before starting creative work — load only what the current stage requires (stages.md + the stage-specific workflow reference). The seed IS the instruction.
3. If Stage 0 is incomplete: initialize structure and ask only for the missing pieces.

Efficiency rule: when the seed is complete and the next stage is clear, move to creative work in the same turn as initialization. The author has already done their part; the agent should not stall on process preparation.

## Stage 0 Capture

**Before initializing**, check whether the project directory already has existing work — a `seed.md` at the project root, in `concepts/`, or any prior stage output. If Stage 0 work exists (even at the root rather than in `concepts/`), read it, copy it to `concepts/seed.md` if needed, and continue from the appropriate stage. Do not re-capture or overwrite existing seed content.

1. Create project structure first: `AGENTS.md`, `progress.md`, `rolling-summary.md`, `concepts/seed.md`, plus standard project subdirectories.
2. Capture the author's raw premise verbatim enough to preserve intent; do not invent missing mechanics.
3. Complete the Stage 0 checklist explicitly:
   - premise spark
   - target subgenre
   - tone
   - likely protagonist
   - likely setting
   - obvious research/safety risks
4. Ask clarification questions before Stage 1 if any of these are ambiguous:
   - protagonist's formal status/authority
   - clandestine unit relationship and whether protagonist knows it exists
   - handler/commander role and organisation
   - codename meaning and whether it is enemy/UK/NATO/protocol/malware
   - spouse/civilian role after escape
   - Act 1 geography and duration
   - antagonist model and deniability layer
   - series continuity constraints
5. After answers arrive, patch `concepts/seed.md`, `progress.md`, and `AGENTS.md` in the same turn.

## Stage 1 Premise Options

For first-in-series launch, produce 3–5 options that vary the story engine, not cosmetic details:

- reluctant recall / duty engine
- hostage-pressure / strategic leverage engine
- codename/history mystery engine
- civilian witness / survival-first engine

Each option should include: protagonist, goal, obstacle, antagonist/force, setting, stakes, moral dilemma, commercial hook, strengths, and risks.

## Required Review Before Author Presentation

Review Stage 1 options with Alex, Morgan, and Vale before presenting.

- Alex: structural engine, protagonist agency, series launch clarity.
- Morgan: reader hook, emotional continuity, spouse/civilian promise.
- Vale: geopolitical plausibility, deniability layers, NATO/infrastructure logic.

Apply fixes before presenting. Do not stop at a conditional review and ask the author whether to fix it. Fix every actionable issue immediately, write a final premise file, update the review gate, update `progress.md` and `AGENTS.md`, then present only the fixed direction and any true author-only decisions. A strong pattern is to recommend a hybrid direction when different options solve different parts of the book: e.g. strategic engine from one option, human opening from another, codename texture from a third.

## Common Pitfalls

1. **Letting the spouse become baggage.** If the author says the spouse helps the escape, preserve that as an active pressure/decision function.
2. **Making infrastructure attacks too absolute.** Prefer cascading regional effects on military response corridors and civilian stability over a simplistic continent-wide off switch.
3. **Treating a deniable mercenary force as faceless.** Later stages need a visible operator/commander whose decisions cause harm.
4. **Advancing after Stage 1 without author approval.** Once reviewed options are presented, mark the project blocked until the author selects or revises the premise direction.
5. **Dropping source links.** If the user provides a reference URL during premise work, add it to the user's `IDEAS.md` and record it in the project seed/research notes.
6. **Over-preparing before creative work.** When a seed is complete and the project just needs initialization + first deliverable, do not load 5-6 reference files before starting. Load only the stage reference + relevant template, initialize the project, and produce the deliverable in the same turn. The author says "use the seed" when the agent is stalling on process preparation instead of doing the creative work the seed enables.
